## 付録 A: 関連するフレームワークとの対応付け

本付録は、OWASP Top 10 for LLM Applications (2026) の 10 項目のリスク エントリと、9 つの外部セキュリティ フレームワークおよび分類体系との対応付けを統合したものです。各 Top 10 エントリごとの「関連フレームワークと分類体系」セクションは削除され、この単一のバージョン固定参照に置き換えられました。

## 本付録の読み方

**カバレッジ対応表**は、各リスクにどのフレームワークが対応しているかを一目で示します。**フレームワーク別セクション**では、具体的な要素の対応付けと、それが適用される理由を説明します。対応付けは、各フレームワークの粗いレベル（戦術、柱/弱点、リスク カテゴリ、制御ドメイン）で行われ、すべての要素は**フレームワーク ソースとバージョン**に記載されている固定フレームワーク バージョンから抽出されています。各セルには、主要な対応付けと、最も関連性の高い補助的なマッピングが表示されます。


**凡例**: ●…主要（中心的な防御線またはリスクの説明）、 ○…補助的（寄与するが、中心的ではない）、 —…該当するマッピングなし

| **LLM07** 誤情報 | ● ASI08 — 連鎖的な障害 | あるエージェントによって生成された誤った状態または証拠が別のエージェントによって信頼されると、マルチ エージェント ワークフロー全体に誤情報が伝播し、複合的で影響の大きい障害が発生します（エージェント間の誤情報伝播、エージェント間の信頼障害）|

| | ● ASI07 — 安全でないエージェント間通信 | 同じスコープの除外項目では、「エージェント間チャネル」をスコープ外の増幅として挙げています。ASI07 は、エージェント間メッセージングを介して伝播する隠しコンテキスト情報へのポインタであり、同等のリスクではありません。|
| **LLM09** ベクトルおよびエンベディングの弱点 | ● ASI04 — エージェント型サプライチェーンの脆弱性 | エンベディング モデルのサプライチェーン: エンベディング モデル自体を検証する必要があります。「バックドア付きのエンベディング モデルは、取り込まれたすべてのジオメトリを破損させる」ためです。|
| | ● ASI06 — メモリおよびコンテキストの汚染 | エンベディング ジオメトリに依存しないエージェントのメモリ汚染は、ここでは対象外であり、ASI06 を参照します。|
| **LLM10** 不適切な出力処理 | ● ASI02 — ツールの不正使用および悪用 | 2026 の追加項目。本項目の内容に基づいて正当化されます。汎用 LLM が出力検証を行わずに応答を特権拡張機能に渡すと、拡張機能が悪用されてシャットダウンされます。|
| | ● ASI05 — 予期しないコード実行 (RCE) | 基本的なクロス ウォーク マッピングです。検証されていない LLM 出力がシェル、`exec`、または `eval` に到達し、リモート コード実行につながるという、本項目のコア リスクと一致します。|
| | ● ASI09 — 人間とエージェント間の信頼の悪用 | 標準的なクロス ウォーク ベース ライン マッピングです。ASI09 では、不適切な出力処理が LLM リスクの要因として挙げられています。内容の一致は緩やかです。本項目のシナリオはマシン間通信（検証されていない出力がシェル、ブラウザ、またはデータベースに到達する）に関するものですが、ASI09 は人間のオペレーターを欺くことに関するものです。共通するテーマは、検証されていないモデル出力が下流の信頼判断に到達することです。|

## OWASP GenAI Data Security 2026 (DSGAI) — v1.0 (2026-03-17)

*各行は、LLM Top 10 リスクを OWASP GenAI Data Security 2026（DSGAI）のリスク カテゴリに対応付けます。主要要素（●）は最も近いデータ セキュリティ ピアを示し、補助要素（○）は最も関連性の高い隣接データ リスクを示します。*

| リスク | 要素 | 関連性 |
|---|---|---|
| **LLM01** プロンプト インジェクション | ● DSGAI01 — 機密データの漏洩 | インジェクションが成功すると、情報漏洩とデータ流出が主な結果となり、システムプロンプトコンテンツ、取得したプライベートドキュメント、インフラストラクチャの詳細がモデルから流出します。 |
| | ● DSGAI06 — ツール、プラグイン、エージェントのデータ交換リスク | インジェクションは MCP サーバーとサードパーティ ツール パッケージを経由して行われ、そこで悪意のあるツール説明と固定されていない接続により、侵害されたモデルが接続されたシステム全体で動作します。 |
| | ○ DSGAI09 — マルチ モーダル キャプチャとクロス チャネル データ漏洩 | ステガノグラフィ画像と不可視 Unicode ペイロードは、人間が目にすることのない命令を送信し、Markdown 画像 URL のレンダリングは盗まれたデータを外部に送り返します。|
| | ○ DSGAI16 — エンドポイントとブラウザ アシスタントの過剰アクセス | 信頼できないページを自動要約するブラウザ、IDE、および電子メール アシスタントは、ゼロ クリックでの文書流出から IDE 構成フラグの反転まで、間接インジェクションのチャネルとなります。|
| | ○ DSGAI04 — データ、モデル、およびアーティファクトの汚染 | RAG コーパスまたは永続メモリ内の汚染されたエントリが 1 つあると、それを読み取る後続のすべてのセッションが汚染され、インジェクションのセッション間伝播経路となります。|

| | ● DSGAI18 — 推論とデータ再構築 | メンバーシップ推論、エンベディング反転、内部状態反転は、コンテンツを直接受け取ることなく、測定可能なモデル動作から保護されたデータを再構築します。|
| | ○ DSGAI15 — 過度に広いコンテキスト ウィンドウとプロンプトの過剰共有 | スコープが設定されていないドライブ、従来のアクセス許可、および自動的に追加される完全なレコードにより、タスクが必要とする以上の機密データがモデルに供給され、これがほとんどのインシデントを引き起こす上流の過剰共有となります。|
| | ○ DSGAI08 — コンプライアンス違反と規制違反 | 情報漏洩は規制上の結果を招き、EU AI 法、GDPR、HIPAA、CCPA の義務と、それらの違反通知期限が発動します。|

|  | ○ TVM 脅威および脆弱性管理 | 開発パイプライン内で静的、動的、および対話型のアプリケーション セキュリティ テストを実施し、エージェント拡張機能の脆弱性をリリース前に特定します。 |
| **LLM04** サプライチェーン | ● STA サプライチェーン管理、透明性、および説明責任性 | SBOM/AIBOM/ML-SBOM インベントリ、サプライヤー審査、および暗号署名と透明性ログに裏打ちされた出所（プロベナンス）情報と、当該ドメインを直接的に対応させます。 |
|  | ● MDS モデル開発のセキュリティ | モデル署名と動作評価を通じて、モデルの改ざんやバックドアに対抗し、アダプタのマージ、フォーマット変換、量子化の各工程において完全性を維持します。 |
|  | ○ TVM 脅威および脆弱性管理 | サービング フレームワークやモデル内の脆弱または古いコンポーネントをスキャンし、依存関係チェーン全体にわたってパッチ適用ポリシーを強制します。 |
|  | ○ CEK 暗号、暗号化、および鍵管理 | 暗号によるモデル署名、Sigstore および透明性ログのエントリ、ファイル ハッシュ、完全性チェックを伴うエッジ モデルの暗号化を使用し、アーティファクトの真正性を検証します。 |
|  | ○ CCC 変更管理および構成管理 | 不変の参照、SLSA に準拠したポリシー ベースのリリース ゲート、および CI/CD 全体でのビルド パイプラインの完全性により、プロモーションの境界を強制します。 |
| **LLM05** データおよびモデルの汚染 | ● MDS モデル開発のセキュリティ | 開発ライフサイクル全体を通じて、汚染から学習・微調整（ファイン チューニング）データおよびモデル アーティファクトを保護します。 |
|  | ● DSP データ セキュリティおよびプライバシーのライフサイクル管理 | 入力データの検証、完全性チェック、データセットのバージョン管理を行い、データ ライフサイクル全体で改ざんされた入力を検知します。 |
|  | ○ STA サプライチェーン管理、透明性、および説明責任性 | SBOM/ML-BOM 記録、アーティファクト署名、ベンダー審査を通じてモデルとデータセットの来歴（リネージ）を確立し、拡散された汚染済みモデルに対抗します。 |
|  | ○ LOG ログ記録および監視 | 学習、エンベディング、推論の各段階で統計的および AI ベースの異常検知と動作ドリフト監視を適用し、汚染の影響を顕在化させます。 |
|  | ○ TVM 脅威および脆弱性管理 | 継続的な敵対的レッド チーム演習やトリガー プロービング（誘発テスト）を実施し、汚染時に仕込まれた隠れたバックドアを露呈させます。 |
| **LLM06** 無制限の消費 | ● AIS アプリケーションおよびインターフェースのセキュリティ | レート制限、トークンやコストを考慮した上限設定、入力サイズ検証、事前トークン推定、認証済み推論エンドポイントなど、最前線でのインターフェース制御を適用します。 |
|  | ● BCR 事業継続管理および運用レジリエンス | 需要の急増時や悪用による負荷増大時に、グレースフル デグラデーション（段階的機能縮退）や負荷分散を伴う動的スケーリングを行い、可用性を維持します。 |
|  | ○ IVS インフラストラクチャおよび仮想化のセキュリティ | リソース割り当ての管理や推論インフラストラクチャの堅牢化（セキュアでない逆シリアル化の無効化や、共有推論におけるサイド チャネル攻撃対象領域の縮小など）を行います。 |
|  | ○ LOG ログ記録および監視 | コストの発生源を継続的に監視し把握するとともに、通常の動作ベースラインと比較してリソース消費の激しいツール利用を検知します。 |
|  | ○ IAM アイデンティティおよびアクセス管理 | API 鍵、ユーザー、チーム、アカウントごとにクォータや支出上限を設定および制限し、推論エンドポイントの認証を行うことで、盗用された資格情報による悪用被害を抑止します。 |
| **LLM07** 誤情報 | ● AIS アプリケーションおよびインターフェースのセキュリティ | クレームとアクションを分離し、ツール呼び出しを意味的に検証し、検証シグナルや必須フィールドを含む構造化出力を要求し、実行時にモデルのクレームを検証します。 |
|  | ○ TVM 脅威および脆弱性管理 | ユーザーに誤情報が届く前に捕捉するため、意図的に誤解を招くシナリオを用いた敵対的評価や継続的なテストを実施します。 |
|  | ○ LOG ログ記録および監視 | クレーム、裏付けとなる証拠、および結果を記録し、経時的に誤情報のパターンを監視します。 |
|  | ○ STA サプライチェーン管理、透明性、および説明責任性 | モデルが指定したパッケージや依存関係が実際に存在し信頼できるものであることを検証することで、幻覚（ハルシネーション）を利用した依存関係攻撃や安全でない生成コードの問題に対処します。 |
| **LLM08** 隠しコンテキストの意図せぬ公開 | ● AIS アプリケーションおよびインターフェースのセキュリティ | 隠しコンテキストをインターフェース露出のリスクと見なし、コンテキスト ウィンドウに入力される情報を精査し、アプリケーション層のガードレールを適用し、プロンプトを信頼するのではなく独立した管理策を強制します。 |
|  | ○ IAM アイデンティティおよびアクセス管理 | モデルとは独立して認可とアクセス制御を強制し、エージェント間で権限を分割することで、露出したコンテキストによって機能が許可される事態を防ぎます。 |
|  | ○ CEK 暗号化および鍵管理 | シークレットを管理されたストアに外部化することで、認証情報、トークン、接続文字列がプロンプトに含まれないようにします。 |
| **LLM09** ベクトルおよびエンベディングの弱点 | ● IAM アイデンティティおよびアクセス管理 | インデックス クエリ内でテナント アイデンティティのスコープを限定し、サーバー側での検証、テナントごとのエンドポイント認証、およびチャンク レベルのアクセス制御を実施します。 |
|  | ● DSP データ セキュリティおよびプライバシーのライフサイクル管理 | 出所（プロベナンス）を追跡し、信頼レベルを分離し、ソースと共に埋め込みデータを削除し、エンベディング データのライフサイクル全体にわたって保持、保存時の暗号化、およびバックアップの機密性を監査します。 |
|  | ● LOG ロギングおよび監視 | 取り込み時および取得時に異常検知を適用し、テナント フィルターの回避やテナント間アクセスがないか監視するために、変更不可能な取得ログを保持します。 |
|  | ○ CEK 暗号化および鍵管理 | アプリケーション層とは別に管理される鍵を使用して保存時のエンベディング データを暗号化し、エンベディング API 鍵をシークレットとして扱います。 |
|  | ○ AIS アプリケーションおよびインターフェースのセキュリティ | エンベディングおよび類似性検索のエンドポイントを「第 1 級の API」として認証し、テナントごとのレート制限を適用するとともに、生の類似性スコアを非公開にします。 |
|  | ○ STA サプライチェーン管理、透明性、および説明責任性 | バックドアが仕込まれたエンコーダのリスクがないかエンベディング モデルを検証し、エンコーダおよびインデックス化されたコンテンツの出所（プロベナンス）を追跡します。 |
| **LLM10** 不適切な出力処理 | ● AIS アプリケーションおよびインターフェースのセキュリティ | モデルの応答を信頼できない入力として検証し、後続の処理系（インタプリタ）に渡る前に、コンテキストに応じた出力エンコーディング、パラメータ化クエリ、コンテンツ セキュリティ ポリシー（CSP）を適用します。 |
|  | ○ LOG ログ記録と監視 | モデルの出力をログに記録・監視し、後続の処理における悪用パターンを検知できるようにします。 |
|  | ○ IAM アイデンティティおよびアクセス管理 | ゼロ トラストの考え方に基づき、モデルを他のユーザーと同様に扱い、その出力がエンドユーザーの権限を超える権限を継承しないようにします。 |

## OWASP AIVSS (AI Vulnerability Scoring System) — v0.8

*各行には、LLM Top 10 のエントリが生成または供給する可能性のある OWASP AIVSS Agentic AI Core Security Risk が一覧表示されています。主要要素はエントリが最も直接的に可能にするリスクを、補助的要素はセカンダリ パスを示します。AIVSS は、これらのエージェント型リスクの深刻度をスコアリングします。*

| リスク | 要素 | 関連性 |
|---|---|---|
| **LLM01** プロンプト インジェクション | ● AIVSS-10 エージェントの目標と指示の操作 | 細工されたメッセージによってシステム プロンプトの役割と機能の制限が上書きされ、モデルが意図された範囲外で動作するようにリダイレクトされます。 |
| | ● AIVSS-1 エージェント型 AI ツールの不正使用 | 注入された入力によって、ファイル システムやシェルから電子メールやクラウド API に至るまで、エージェントが呼び出しを許可されているツールが不正に呼び出されます。 |
| | ● AIVSS-2 エージェントのアクセス制御違反 | エージェントは、ユーザーの昇格された資格情報を使用して動作しながら、攻撃者が仕込んだテキストを読み取り、攻撃者が直接アクセスできない特権アクションを実行します。 |
| | ● AIVSS-6 エージェントのメモリおよびコンテキストの操作 | 長期メモリまたは RAG コーパスに書き込まれたインジェクションによって、汚染されたストアを読み取る後続のすべてのセッションが汚染され、会話全体にわたって侵害が持続します。 |
| | ○ AIVSS-7 エージェントによる重要システムとの安全でない相互作用 | エージェントがシェル、ファイル システム、またはクラウド API へのアクセス権を保持している場合、インジェクション攻撃は任意のコマンド実行とホスト上での破壊的なアクションへと拡大します。 |
| | ○ AIVSS-3 エージェントの連鎖的障害 | ツールの出力が共有コンテキストウィンドウに再入力されるため、1つのインジェクション攻撃が連鎖してさらにツール呼び出しにつながったり、複数のステップにわたって自己複製したりする可能性があります。 |
| | ○ AIVSS-4 エージェントのオーケストレーションとマルチ エージェントの悪用 | インジェクション攻撃はエージェント間で自己複製し、マルチ エージェント ワークフローにおいて、侵害されたエージェントから他のエージェントへと拡散する可能性があります。 |
| **LLM03** 過剰な主体性 | ● AIVSS-1 エージェント型 AI のツールの悪用 | 拡張機能は、タスクに必要な機能を超えて、例えば変更、削除、送信などの操作に読み取り専用アクセスをバンドルするなど、本来使用されるべきではない機能を呼び出します。そのため、誤動作したモデルが本来使用されるべきではない機能を呼び出してしまう可能性があります。 |
| | ● AIVSS-2 エージェントのアクセス制御違反 |拡張機能は、過度に広範または汎用的な高権限アイデンティティを使用して下流システムに接続し、エージェントがユーザー自身の認証範囲をはるかに超えて動作することを可能にします。|
| | ● AIVSS-7 セキュアでないエージェントの重要システムとの相互作用 | 意図しないコマンドをフィルタリングできないオープン エンドのシェル コマンド拡張機能、または過度に自律的なコーディング エージェントは、有害なアクションを実行し、実稼働インフラストラクチャを破壊する可能性があります。|
| | ○ AIVSS-3 エージェントの連鎖的障害 | レート制限やサーキット ブレーカーがない場合、暴走する拡張機能の呼び出しが連鎖的に下流システムの障害を引き起こします。|
| | ○ AIVSS-4 エージェントのオーケストレーションとマルチ エージェントの悪用 | 悪意のある、または侵害されたピア エージェントは有害なアクションをトリガーする可能性があり、連鎖したエージェント呼び出し間でユーザー コンテキストが保持されないと、影響範囲が拡大します。|
| | ○ AIVSS-10 エージェントの目標と命令の操作 | 細工された受信メールなど、直接または間接プロンプト インジェクションは、エージェントを意図しない特権アクションに誘導するトリガーとなります。|
| **LLM04** サプライチェーン | ○ AIVSS-8 エージェント サプライチェーンと依存関係のリスク | 侵害されたサードパーティ パッケージ、事前学習済みモデル、LoRA アダプタ、変換パイプラインまたはマージ パイプラインは、エージェントが継承する依存関係の基盤となるため、改ざんされたモデル サプライチェーンのアーティファクトは、エージェントのサプライチェーンにもなります。 |
| **LLM05** データおよびモデルの汚染 | ○ AIVSS-6 エージェント メモリとコンテキストの操作 | 攻撃者は、エージェントの永続メモリやセッションをまたいだ推奨事項を汚染する隠し命令を Web コンテンツに埋め込むため、エージェントは攻撃者が制御するロジックを優先するようになります。 
| | ○ AIVSS-8 エージェント サプライチェーンと依存関係のリスク | バックドアが仕掛けられたモデルや安全でないシリアル化されたアーティファクトがパブリック リポジトリを通じて配布されると、下流のエージェントがロード時に継承する隠しトリガーが存在します。 |
| | ○ AIVSS-3 エージェントの連鎖的障害 | 汚染された入力はマルチ エージェントおよびエンタープライズ ワークフロー全体に伝播し、共有エンベディングメモリ層によって汚染がテナント間で拡散します。|
| **LLM06** 無制限の消費 | ○ AIVSS-1 エージェント型 AI のツールの悪用 | 悪意のあるツールがエージェントを再帰的または無限のツール呼び出しループに陥らせ、タスクのニーズをはるかに超えるトークン消費とコストを引き起こします。|
| | ○ AIVSS-3 エージェントの連鎖的障害 | エージェントおよび MCP プロトコルは、単一のリクエストを連鎖的な下流操作に増幅するため、1 つのタスクが多数のツール呼び出しに分岐し、予算と可用性を枯渇させます。|
| | ○ AIVSS-8 エージェント サプライチェーンと依存関係のリスク | 攻撃者がオープンソース リポジトリ上のスキルなどの悪意のあるツールを公開し、開発者がそれをエージェントの依存関係として組み込むと、統合後にトークンの枯渇を引き起こします。|
| **LLM07** 誤情報 | ● AIVSS-3 エージェントの連鎖的障害 | あるエージェントによって生成された誤った状態または証拠が別のエージェントによって信頼されると、マルチ エージェント ワークフロー全体に伝播し、複合的な重大な障害を引き起こします。|
| | ○ AIVSS-1 エージェント型 AI のツールの悪用 | モデルの出力がツール呼び出しを駆動するため、呼び出しが現実世界の状態と意図に対して検証されない限り、誤った状態推論は意図しないアクションを引き起こします。|
| | ○ AIVSS-7 エージェントと重要システムのセキュアでない相互作用 | 払い戻しの誤った承認や誤ったアラートの発報など、誤った結論は、金銭的損失や業務の中断を引き起こす、自動化された重大なアクションを駆動します。|
| **LLM08** 隠しコンテキストの意図せぬ公開 | ○ AIVSS-2 エージェントのアクセス制御違反 | 隠しコンテキストから公開された権限ルールとユーザー ロール指示により、認可モデルが明らかになり、LLM とは独立してアプリケーションが適用すべき制御を回避するプロービングを誘発します。 |
| | ○ AIVSS-1 エージェント型 AI のツールの悪用 | 隠されたツール リストとパラメータ スキーマを抽出することで、攻撃者はアプリケーションを特定のツール呼び出しに誘導するための具体的なターゲットを得ることができます。 |
| **LLM09** ベクトルおよびエンベディングの弱点 | ○ AIVSS-6 エージェント メモリとコンテキストの操作 | 取得時汚染により、ベクトルを基盤とするエージェント メモリのジオメトリが操作され、攻撃者のコンテンツが信頼できるコンテキストとして取得されます。一方、非幾何学的なメモリ汚染はエージェント フレームワークに委ねられます。 |
| | ○ AIVSS-8 エージェント サプライチェーンと依存関係のリスク | バックドアが仕込まれたエンベディング モデルは、取り込まれたすべてのデータのジオメトリを破損させ、脆弱なベクトルデータ ベースの依存関係は、漏洩したインデックスがソース文書に復元可能であるため、リスクをさらに高めます。|
| | ○ AIVSS-2 エージェントのアクセス制御違反 | テナントへのアクセス制御が適用される前に、共有インデックス全体に対して類似性検索が実行されるため、攻撃者は認証によってブロックされるべき他のテナントのコンテンツを推測したり、アクセスしたりする可能性があります。|
| **LLM10** 不適切な出力処理 | ○ AIVSS-7 エージェントの重要システムとのセキュアでない相互作用 | 検証されていないモデル出力がシェル、exec/eval、SQL、またはファイル パスのシンクに到達すると、バックエンド システム上でリモート コード実行、SQL インジェクション、またはパス トラバーサルが発生します。|
| | ○ AIVSS-1 エージェント型 AI のツールの悪用 | 汎用 LLM の検証されていない応答が特権拡張機能に渡されると、拡張機能が誤用され、例えば意図しないシャットダウンが強制されます。|
