## LLM09:2026 ベクトルおよびエンベディングの弱点

### 解説

ベクトルおよびエンベディングの弱点は、テキスト、画像、コード、音声などを数値表現に変換し、類似性検索を用いてモデルが認識する情報を決定するあらゆる LLM アプリケーションにおいてセキュリティ リスクとなります。最もよく知られているのは検索拡張生成（RAG）ですが、ベクトル ベースのエージェント メモリ、セマンティック キャッシュ、重複排除パイプラインも同様の仕組みで動作しています。データ ソースとプロンプトの間に類似性検索が介在する場合、エンベディング層はアプリケーションの信頼境界の一部となります。

これらの弱点はプロンプト インジェクションとは異なります。モデルの命令追従動作ではなく、エンベディング空間の幾何学的構造と類似性検索の機構を悪用します。多くの場合、取得されたコンテンツに悪意のある命令が全く含まれていない場合でも攻撃が成功します。分かりやすい例えとして、汚染はシステムを誤動作させ、反転は情報を漏洩させ、妨害はシステムを沈黙させ、アクセス制御の失敗はシステムを無差別にします。

本稿では、エンベディング層に依存する攻撃について解説します。取得コンテンツを介した間接プロンプト インジェクションについては、「LLM01:2026 プロンプト インジェクション」、エンベディング モデルの学習時の汚染については、「LLM05:2026 データおよびモデルの汚染」、ベクトル ストア ライブラリのシリアル化の欠陥については、「LLM04:2026 サプライチェーン」、エンベディング ジオメトリに依存しないエージェント メモリ攻撃については、「ASI06:2026 メモリおよびコンテキストの汚染 」(OWASP Top 10 for Agentic Applications) で取り上げています。ベクトルレス検索システム (BM25 のみ、LLM ネイティブ ツリー ナビゲーション) は、非幾何学的なリスクを継承しますが、LLM09 の攻撃対象領域はありません。

### リスクの一般的な例

#### 1. 共有類似性検索を介したテナント間情報漏洩

マルチ テナント環境では、アプリケーション層でアクセス制御が適用される前に、インデックス全体に対して類似性検索が実行されることがよくあります。攻撃者は、細工されたクエリを用いてインデックスをプローブし、検索結果の数、スコア分布、実行時間から、他のテナントの文書の存在、トピック、おおよそのボリュームを推測できます。これは、文書自体を直接見ることなく可能です。すべての文書が正しくタグ付けされ、すべての API 呼び出しが認証されている場合でも、アクセス制御の決定はエンベディング空間検索の実行後に行われるため、この攻撃は成功します。ベクトル データベース ソフトウェアにおける認証に関する従来の脆弱性、例えば CVE-2025-64513（Milvus、偽造された sourceID ヘッダーによる認証回避、CVSS 9.3）や CVE-2025-69286（RAGFlow、予測可能なトークン導出によるアカウント乗っ取り、CVSS 9.3）などは、本稿の範囲外ではあるものの、幾何級数的なリスクを増大させます。ベクトル ストアからの情報漏洩は、反転によってソース文書を復元できるため（リスク #2）、ベクトル データベースにおける認証バグは、文書データベースや KV ストアにおける同様のバグよりも深刻な影響を及ぼします。

#### 2. エンベディングの反転

保存されたエンベディングを反転することで、ソース文字列を復元できます。報告されている復元率は、文エンベディングからの単語の約 50～70% から、エンコーダごとに反転モデルを学習する Vec2Text法（Morris 他、2023 年）による 32 トークンの短い入力の 92% の正確な復元まで多岐にわたります。ZSInvert（C. Zhang 他、2025 年）と Zero2Text（Kim 他、2026 年）は、エンコーダ固有の学習を必要としないゼロ ショット方式で動作し、クロスドメインおよびブラックボックス環境で機能し、ストレージで追加される差分プライバシー ノイズに対しても有効です。運用面では、ベクトル データベースのバックアップ、サードパーティ サービスに送信されるエンベディング、および設定ミスのあるクラウド ストレージを通じて公開されるエンベディングは、基となる文書の漏洩と同等に扱うべきです。GDPR および同様の規制の下では、侵害通知はデータ主体へのリスクに依存しますが、最新のエンベディングは反転可能であるため、そのリスクは現実のものです。

#### 3. 検索時データ汚染

公開されているスクレイピング パイプライン、ファイル アップロード、パートナー フィード、または侵害された内部ソースなどを介してコーパスに書き込み可能な攻撃者は、ターゲット クエリに近いエンベディング コードを持つコンテンツを作成できます。ユーザーがそのクエリを送信すると、攻撃者のコンテンツが取得され、信頼できるコンテキストとして LLM に渡されます。公開されている攻撃では、数百万件のコーパスやブラックボックス システムに対しても、少数の汚染された文書で高い成功率を達成しています。攻撃を成功させるには、2 つの条件が同時に満たされる必要があります。汚染されたコンテンツが取得されること（幾何学的条件）と、レスポンスを誘導すること（生成条件）です。防御側はどちらの層でも介入できます。MITRE ATLAS では、このクラスは永続性戦術の「AML.T0070（RAG 汚染）」として分類されています。エンベディング モデル自体の学習時の汚染は LLM05:2026 です。

#### 4. 検索妨害

攻撃者は、「ブロッカー」文書を挿入することで RAG システムを機能停止させることができます。ブロッカーとは、特定のクエリに対して検索されるように設計されたコンテンツであり、LLM が応答を拒否したり、情報が不足していると主張させたりするように仕向けます。汚染とは異なり、ブロッカーには悪意のある指示は含まれていません。検索機構と LLM の安全動作を悪用します。ターゲットのエンベディング モデルや LLM にアクセスすることなく、ブラックボックス最適化によって生成された単一のブロッカー文書で十分です。これは、検索層に対する可用性攻撃です。

#### 5. 類似性検索によるメンバーシップ推論

攻撃者は、特定の文書（医療記録、訴訟書類、人事苦情など）がインデックスに存在するかどうかを知りたいのであって、その文書の内容は知りません。アプリケーションがクライアントに生の類似性スコアまたは距離を返す場合、インデックスは LLM を介さずに直接メンバーシップ オラクルとして機能します。生成された回答のみが返される場合でも、攻撃者は部分的な文書や改ざんされたクエリを送信し、応答を分析することでメンバーシップを推測できます。コンテンツが保護されている場合でも、メンバーシップ情報自体が機密情報となる可能性があります。

#### 6. セマンティック キャッシュと重複排除の汚染

セマンティック キャッシュと類似コンテンツ検出は、コサイン類似度閾値を使用して 2 つのコンテンツが「同一」であるかどうかを判断します。この閾値のわずかに上または下に位置するコンテンツを作成できる攻撃者は、キャッシュ エントリを改ざんして、意味的に同等のすべてのクエリに攻撃者のテキストを返すようにしたり、改ざんされたコンテンツの類似コンテンツで重複排除を回避したり、正当な新規コンテンツを重複コンテンツとして密かに削除させたりすることができます。Wu 他（2026 年）は、AWS、Azure、Alibaba のデプロイメント全体でエンド ツー エンドのセマンティック キャッシュ汚染を実証しています。Z. Zhang 他（2026 年）は、ターゲット エンコーダにアクセスすることなく、サロゲート エンベディング モデルを用いて閾値をまたぐベクトルを生成するブラックボックス型のキー衝突攻撃を示しています。これら 3 つの障害モードはすべてエンベディング空間の幾何学的構造に依存しており、文書レベルの管理策では検出できません。

#### 7. マルチ モーダル エンベディングの汚染

CLIP や ColPali などのクロス モーダル エンコーダは、画像、音声、コード、テキストを 1 つのベクトル空間にマッピングします。非テキスト コンテンツを提供できる攻撃者は、機密性の高いテキスト クエリに近いエンベディングを持つ画像を作成できます。ユーザーがそのクエリを送信すると、画像は信頼できるコンテキストとして取得されます。MM-PoisonRAG（Ha 他、2025 年）と Poisoned-MRAG（Liu 他、2025 年）は、マルチ モーダル RAG パイプライン全体にわたる局所的および全体的な汚染を実証しています。「One Pic is All it Takes」は、標的型および汎用的な VD-RAG 汚染には 1 枚の画像で十分であることを示しています。人間のレビュー担当者にとっては、その画像は特に目立ったものではないように見えるし、ペイロードがテキストではないため、テキスト ベースのコンテンツ スキャンでも検出されません。

### 防止および軽減戦略

#### 1. 権限とアクセス制御

テナント スコープは、取得後のフィルタとしてではなく、インデックス クエリ内で強制的に適用し、サーバー側で検証します。クライアントから提供されるスコープは、あくまで推奨であり、制御ではありません。エンベディング エンドポイントと類似性検索エンドポイントは、テナントごとのレート制限を持つ第 1 級の API として認証します。機密性の高いワークロードの場合は、テナントごと、またはトラスト ゾーンごとに物理的に分離されたインデックスを使用します。アクセス制御はチャンク レベルで適用します。大部分が公開されている文書にも、機密情報を含む段落が含まれる可能性があります。

#### 2. データ検証、ソース認証、および出所

エンベディング前にコンテンツを正規化します。抽出時に、ゼロ幅文字、白地に白文字、および Unicode 同形文字を削除します。すべてのエンベディングについて出所（ソース、取り込み時間、トラスト ティア、パイプライン バージョン）を追跡し、侵害されたバッチを無効化して監査できるようにします。機密性の高いインデックスに使用される外部ソース コンテンツには、人間のレビューを適用します。エンベディング モデル自体を検証します。バックドアが仕込まれたエンコーダは、取り込まれたすべてのデータのジオメトリを破損させます。

#### 3. 信頼レベルによるデータ分離

信頼レベルが異なるコンテンツ（外部 Web データ、内部機密文書、パートナー データなど）は、厳密な分離なしにインデックスを共有してはなりません。インデックス レベルの分離は、共有インデックス上の分類タグよりも優れています。なぜなら、設定ミスによる影響を排除できるからです。

#### 4. 取り込みと検索における異常検出

検索ハイジャック攻撃の兆候として、一般的なクエリの広範囲に異常に近接する新しいベクトルを検出します。類似度の高い一致を過剰に返すクエリ、エンベディング エンドポイントにおける異常なトラフィック量（クエリ ベースの反転攻撃の前兆）、取り込み後に予想以上に急速に増加するクラスタを監視します。クライアントに生の類似度スコアを返さず、検索ランキング層でノイズと多様性を追加し、オラクルとしてクエリされる可能性のあるエンドポイントにはレート制限を適用します。エンコーダー間の再ランキングは攻撃コストを増加させますが、出所と取り込みの制御に取って代わるものではありません。現代の攻撃は、検索とランキングの両方を同時に標的としています。

#### 5. ストレージ ライフサイクルの制御

ソース文書が削除されたら、一定期間内にエンベディング データも削除し、照合監査で検証します。ベクトル データベースのバックアップは、ソース文書と同じ機密レベルとして扱います。保存されているエンベディング データは、アプリケーション層とは別に管理される鍵で暗号化します。エンベディング モデルをローテーションする際は、古いベクトルと新しいベクトルを混在させるのではなく、コーパスを再エンベディングします。異種エンベディングは、類似性挙動に悪用可能なギャップを生み出します。エンベディング API 鍵は秘密情報として扱います。鍵が漏洩すると、攻撃者は正確なエンコーダーへのクエリ アクセスが可能になります。

#### 6. 監視、ログ記録、インシデント対応

検索アクティビティ（テナント スコープ、クエリ、返却 ID、類似度スコア）の不変ログを保持します。テナント フィルタのバイパス試行、テナント間データ取得の異常、および異常なエンベディング API の使用状況を監視します。インシデント対応プレイブックを更新し、「エンベディングのみ」の漏洩が GDPR 第 33 条および類似の規定に基づく侵害評価および通知の対象となるソース データ漏洩として扱われるようにします。

### 攻撃シナリオの例

#### シナリオ #1: 公開データ取り込みパイプラインへのエンベディング類似性攻撃

ある企業の RAG システムは、スケジュールに基づいて公開文書やフォーラムの投稿をスクレイピングしています。攻撃者は、「第 3 四半期の売上予測は？」といった特定の社内クエリの近くにエンベディングが配置されるように設計された投稿を公開します。従業員がこの質問をすると、攻撃者のコンテンツが取得され、LLM に渡されます。同じテキストをチャットに貼り付けても効果はありません。この攻撃が有効なのは、攻撃者がエンベディング空間においてターゲット クエリの近くにコンテンツを配置できるからです。

#### シナリオ #2: 共有ベクトル インデックスにおけるテナント間推論

マルチ テナント SaaS 製品は、アプリケーション層でテナント フィルタリングを行う共有ベクトル インデックスを使用しています。テナント A がプロービング クエリを送信すると、フィルタが適用される前に、テナント B のエンベディングを含むすべてのエンベディングに対して類似性検索が実行されます。テナント A はテナント B の文書を直接見ることはありませんが、タイミングのずれ、結果数、スコア分布のギャップから、テナント B のコンテンツの存在と大まかなトピックが明らかになります。テナント A は多数のクエリを実行することで、テナント B のデータに関する有用なマップを作成します。このカテゴリの実際の事例としては、CVE-2025-69286（RAGFlow）が挙げられます。この脆弱性では、広く普及しているオープンソースの RAG エンジンにおいて、予測可能なトークン生成によってアカウント間の侵害が発生しました。

#### シナリオ #3: 漏洩したベクトル ストアからのエンベディング反転攻撃

クラウドの設定ミスにより、実稼働環境のベクトル データベースのバックアップが漏洩しました。基となる文書（個人情報を含む顧客会話ログ）は個別に暗号化されており、漏洩していないため、当初は「エンベディング データのみが漏洩した」として、このインシデントは低深刻度と分類されました。攻撃者は、盗まれたエンベディング データに対してゼロ ショット反転攻撃を実行し、元のエンコーダにアクセスすることなく、個人情報を含むソースコンテンツの大部分を再構築しました。この事案は、情報源文書の侵害と同等とみなされ、通知義務が再評価されます。「エンベディングのみ」はセーフ ハーバー（安全地帯）分類には該当しません。
