## LLM06:2026 無制限の消費

### 解説

無制限の消費は、LLM アプリケーションが過剰かつ制御不能な推論を許容する際に発生し、攻撃者がサービス可用性を阻害したり、持続不可能な経済的損失を与えたり、モデルのクローン作成を通じて知的財産を盗み出したりすることを可能にします。これは、リソース消費に対する適切な管理策の欠如という、共通の脆弱性を悪用することによって発生します。

LLM は、特にクラウド環境や従量課金制環境において、高い計算負荷を伴うため、リソースの悪用や不正使用に対して本質的に脆弱です。この脅威の決定的な特徴は、コストの非対称性です。攻撃者は、巧妙に作成されたプロンプト、盗まれた資格情報、または操作されたワークフローなどを通じて、自身にとってごくわずかなコストで、不釣り合いに高コストな計算処理を引き起こすことができます。

このリスクは、出力予算が大きかったり制約が不十分だったりする拡張思考・推論モデルの普及、リクエストごとの計算コストを大幅に増加させるマルチ モーダル モデル、単一のリクエストを連鎖的な下流操作に増幅させるエージェント型アーキテクチャやツール使用プロトコル（MCP など）、そして新たなサプライチェーン攻撃対象領域を生み出す共有推論インフラストラクチャの普及によってさらに深刻化しています。従来の要求レート制限だけではもはや十分ではありません。効果的な防御には、トークンを考慮したコスト制御、厳格な支出上限、エージェント レベルのサーキット ブレーカー、そして継続的なコスト帰属の監視が必要です。

### リスクの一般的な例

#### 1. 可変長入力の大量送信と出力爆発

攻撃者は、処理効率の悪用により、長さの異なる多数の入力を LLM に送り込むことで過負荷状態に陥らせることができます。これによりリソースが枯渇し、システムが応答不能になる可能性があり、サービス可用性に重大な影響を与えます。また、微調整（ファイン チューニング）汚染による出力爆発も含まれます。これは、悪意のある単一の学習サンプルによってモデルのシーケンス終了動作が破られ、すべてのリクエストで出力が最大長まで押し上げられるというものです（Gao et al., 2024 年）。

#### 2. ウォレット拒否（DoW）

攻撃者は、大量の操作を開始することで、クラウド ベースの AI サービスの従量課金モデルを悪用し、プロバイダーに持続不可能な財政的負担をかけ、財務的破綻のリスクを高めます。

#### 3. 大規模コンテキストの悪用

制限値に近いリクエストの繰り返し、コンテキストの蓄積、およびアプリケーション側での再チャンキングは、過剰な計算能力とメモリを消費します。多くの API はコンテキスト ウィンドウを超える入力を即座に拒否するため、持続的なリスクは、制限内に収まりながらもリクエストごとのコストを増大させるリクエストから生じます。

#### 4. 推論ループと思考トークンの枯渇

攻撃者は、一見無害に見える短いプロンプトを作成し、拡張思考モデルを長時間または終了しない推論ループに陥らせることでリソース枯渇を引き起こします。これにより、入力サイズ フィルタを回避しながら、膨大な思考トークンを消費します（Li et al., 2025 年）。これらのプロンプトは小さく、正当に見えるため、標準的な入力検証では保護されません。

#### 5. リソース過剰消費に最適化された敵対的入力

攻撃者は、計算コストを最大化する入力を作成するために最適化技術を使用します。これは、単にモデルにリソース集約型のタスクを実行させるのとは異なり、スポンジの例（Shumailov et al., 2020 年）や敵対的な視覚的摂動などが含まれます。本書では、勾配ベースおよび勾配フリーの手法を用いた敵対的入力の最適化について解説します。推論ループ攻撃とは異なり、これらの手法ではプロンプト設計のみに頼るのではなく、入力空間全体にわたる明示的な最適化が必要となります。

#### 6. マルチ モーダル入出力

マルチ モーダル モデルは、画像、音声、動画を大量のトークンに変換するため、単一のリクエストにかかるコストは、同等のテキストのみのリクエストよりも大幅に高くなる可能性があります。正確なオーバーヘッドは、モデル、プロバイダ、解像度、メディアの長さ、および前処理パイプラインによって異なります。

#### 7. モデル抽出と蒸留による盗難

攻撃者は、細工された入力を用いてモデル API にクエリを実行し、部分的なモデルを複製したり、機能的に同等のモデルを微調整したりするのに十分な出力を収集します。ロジットと対数確率が漏洩すると、抽出が著しく加速されます（Carlini et al., 2024 年）。タイミング監視や共有インフラストラクチャの監視によるモデルの重みやアーキテクチャのサイド チャネル抽出は、LLM02:2026「機密情報の開示」で規定されています。

#### 8. エージェントとツール間の相互作用によるモデル リソースの過剰消費

攻撃者は、LLM ベースのアプリケーションを再帰的または無限ループに陥らせることで、LLM リソースを過剰に消費するツールを公開する可能性があります。これにより、一見正当なツール操作が、金銭的な負担やサービス品質の低下につながる可能性があります。1 つのツール呼び出しが多数の操作に分岐すると、LLM は単一のタスクから発生する数百もの呼び出しを管理する必要が生じ、トークンの過剰消費を引き起こします。

#### 9. 推論インフラストラクチャの悪用

攻撃者は、LLM サービス フレームワーク（vLLM、TensorRT-LLM、SGLang、Triton、Ollama）の脆弱性を標的にし、安全でない逆シリアル化の欠陥、特殊トークンのインジェクション、および注入されたチャット テンプレートを通じて、サービスをクラッシュさせたり、モデル リソースを枯渇させたりします。

### 防止および軽減戦略

### 1. レート制限と入力サイズ検証

レート制限とユーザー割り当て量を適用し、特定の期間内に単一のソース エンティティが実行できるリクエスト数を制限します。1 秒あたりのリクエスト数だけでなく、1 分あたりのトークン数、1 日あたりのトークン数、およびリクエストあたりの推定コストにも制限を設けます。推論開始前にリクエストを拒否するために、プリフライト トークン推定を使用します。これには、入力が妥当なサイズ制限を超えないことを確認するための検証が含まれます。

#### 2. 厳格な支出上限

API 鍵、ユーザー、チーム、クラウド アカウントごとに、変更不能な予算上限を設定します。これは、急速に増加するワークロードによって超えてしまう可能性のあるアラートしきい値ではなく、上限を超えた場合に推論を停止する強制機構である必要があります。支出上限は、モダリティとツール プロトコル間のコスト差も考慮する必要があります。

#### 3. リソース割り当て管理

リソース割り当てを動的に監視および管理し、単一のユーザーまたはリクエストが過剰なリソースを消費することを防ぎます。

#### 4. サンドボックス技術

LLM のネットワーク リソース、内部サービス、および API へのアクセスを制限します。アプリケーションがアクセスできる範囲を制限することで、攻撃者が抽出したモデル情報やデータを外部に持ち出す能力を制限できます。

#### 5. 段階的な機能低下（グレースフル デグラデーション）

高負荷時でもシステムが完全に停止するのではなく、部分的な機能を維持したまま段階的に機能低下するように設計します。

#### 6. キューイング処理の制限と堅牢なスケーリング

キューイング処理の数と総処理数に制限を設け、動的なスケーリングと負荷分散を組み込むことで、様々な需要に対応し、システムの一貫したパフォーマンスを確保します。

#### 7. 敵対的摂動の検出

モデル入力、特に LVLM（大規模視覚言語モデル）への視覚入力をスキャンし、モデル リソースの過剰消費を引き起こす可能性のある敵対的摂動の痕跡を検出します。

#### 8. リソースを大量に消費するツールの相互作用の検出

エージェントとツールの相互作用を監視し、特定のセッションが明確な終了状態を持たずに再帰的またはリソースを大量に消費する処理を引き起こしているかどうかを特定します。特定のツールが標準的なトークン消費パターンから逸脱していないかを検出するために、ツールの正常な動作のベースラインを確立します。

#### 9. エージェントのサーキット ブレーカー

すべてのエージェント実行に対して、ステップ制限、再帰深度制限、時間制限、および実行ごとのコスト上限を適用します。状態ハッシュを使用して再帰ループを検出します。

#### 10. 推論インフラストラクチャの強化

サービス フレームワークを常に最新の状態に保ちます。安全でない逆シリアル化を無効にし、特殊トークンのパススルーを制限し、すべての推論エンドポイントで認証を強制します。

### 攻撃シナリオの例

#### シナリオ #1: 制御不能な入力サイズ

攻撃者がテキスト データを処理する LLM アプリケーションに異常に大きな入力を送信し、過剰なメモリ使用量と CPU 負荷を引き起こし、システム クラッシュやサービスの著しい速度低下を招く可能性があります。

#### シナリオ #2: 反復リクエスト

攻撃者が LLM API に大量のリクエストを送信し、計算リソースを過剰に消費させ、正規ユーザーがサービスを利用できなくなる可能性があります。

#### シナリオ3：リソース集約型クエリ

攻撃者が LLM の最も計算負荷の高い処理をトリガーするように設計された特定の入力を作成し、GPU 使用時間の長期化とシステム障害の可能性を引き起こします。

#### シナリオ #4: ウォレット拒否（DoW）

攻撃者がクラウド ベースの AI サービスの従量課金モデルを悪用するために過剰な操作を生成し、サービス プロバイダーに持続不可能なコスト負担を強います。

#### シナリオ #5: 機能モデルの複製

攻撃者は LLM の API を利用して合成学習データを生成し、別のモデルを微調整（ファイン チューニング）することで、機能的に同等のモデルを作成し、従来のモデル抽出の制限を回避します。

#### シナリオ #6: LVLM 画像入力への摂動

攻撃者が、LVLM の出力でトークンを過剰消費させるように最適化された摂動を含む敵対的画像入力を作成します（Gao et al., 2025 年）。

#### シナリオ #7: マルチ ターンにわたるツール呼び出しループとツール呼び出しのファン アウト

攻撃者は、エージェントに再帰的な循環タスク、または多数のツール呼び出しを必要とするタスクを実行させる悪意のあるツール（例えば、オープン ソース リポジトリ上の Claude スキル経由）を公開することができます。このツールをエージェントに組み込んだ開発者は、トークンの過剰消費とサービスの不安定化のリスクにさらされます。

#### シナリオ #8: エージェント セッションにおける LLM コンテキストの増大

攻撃者または善意のユーザーがエージェント セッションを開いたままにし、コンテンツを徐々に注入することで、推論のたびに蓄積されたコンテキスト全体を再処理します。コンテキストが増大するにつれて、ターンごとのコストは上昇し、最初のターンでは約 0.001 ドルだったものが、100 ターン目には約 0.50ド ルになります。個々のリクエストは予算内に収まるため、レート制限をトリガーすることはありませんが、多数の同時実行セッションや長時間のセッション全体では、合計で数百ドルに達します。
